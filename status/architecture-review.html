Correctness Against Statute, Which Is Where This Product Can Do Real Harm

A bid platform that is wrong about a threshold, a procedure or an evaluation basis does not inconvenience a customer; it misinforms them about a legal obligation and they act on it. Four defects of that class were found and fixed in Release 2.7. Two of them were wrong for a long time, and each was invisible for the same reason: the correct value existed and nothing read it.

🏴 Northern Ireland was governed by a revoked instrument

The jurisdiction registry declared Northern Ireland under “Public Contracts Regulations 2015 (Northern Ireland)”, with evaluation_basis: MEAT and thresholds pointing at the expired EU set (139,688 / 214,904 / 5,372,609, in a window that ended 2025-12-31).

Three things wrong at once. The instrument was revoked in February 2025. The thresholds were the wrong numbers. And MEAT is the old basis: the Procurement Act 2023 uses MAT, most advantageous tender, which is a substantive change in what a buyer is allowed to weigh, not a rename.

FIXED The ruleset now records evaluation_basis: MAT and points at procurement_pa2023.schedule_1_thresholds_gbp_inc_vat. The generated advisory string reads: “This Northern Ireland bid is judged under the Procurement Act 2023, which extends to Northern Ireland (s.126).”

Honest residue: the internal registry key is still ppr_2016, because the registry builder enforces one jurisdiction per regime. Only the user-facing strings were corrected. Filed OPEN as R27-SEGMENT-13. Do not read this as “the key was corrected”.

🚫 NI buyers were refused a procedure they are entitled to run

A Northern Ireland contract attempting a competitive flexible procedure received HTTP 409. The gate at api/app/routers/crowmark_procurement_stages.py:200–217 asked whether the regime supports user-defined stages, and the answer came from a hand-written frozenset({"procurement_act_2023"}).

The hand-written set was the defect. It encoded a fact that the registry already knew, and the two could not disagree loudly, only silently. It now reads ruleset["supports_user_defined_stages"] at api/app/services/crowmark_procurement_stages.py:73.

FIXED Northern Ireland now declares supports_user_defined_stages: true, justified in the ruleset itself: s.20 sits in Part 3 with no NI disapplication, and what s.84(2) disapplies is Part 6. api/tests/test_crowmark_procurement_stages.py:278 asserts 201 where it previously asserted 409, and the Scotland pairing still asserts 409, which is the control that makes the change meaningful rather than a loosened gate.

📑 Schedule 1 has two goods-and-services thresholds. The platform generated both and read one

PA2023_THRESHOLD_CENTRAL_GOVERNMENT_SUPPLY_GBP = £135,018. PA2023_THRESHOLD_SUB_CENTRAL_SUPPLY_GBP = £207,720. Both were generated into both tiers, TypeScript and Python, from the statute-verified registry. The central government figure was read by no product code. A single line aliased the goods-and-services threshold to the sub-central value, so every buyer was measured against the council figure.

The consequence is exact and it is the wrong direction: a central government buyer with a £150,000 contract was told it was below threshold when it is above. The file’s own comment already warned that applying the wrong one “would report a below-threshold contract as above-threshold”. The distinction was understood, documented, generated and constraint-checked in the database, and then not wired at the one line that displays it.

HALF FIXED web/src/features/public-sector/regulation-logic.ts:116–120 now branches on authorityClass and is reached by two real callers, the transparency page and the pack route, with a reachability guard asserting a product reader exists so the constant cannot fall out of use again.

There is no database column and no API field; the input type marks it optional, so in production every notice still falls to ASSUMED_AUTHORITY_CLASS = "sub_central", flagged authority_class_assumed: true. The correct branch is reachable by code and not by any user. The capture half is R27-SEGMENT-03 and is OPEN. ⚖ The 10% social value floor blocked publication for every buyer. It binds three

A flat PPN_MIN_WEIGHTING_PCT = 10 refused to let any buyer publish a requirement weighting social value below 10%. The floor is real, but it does not bind everyone: it binds central government (PPN 002), the NHS (net zero and social value), and Northern Ireland public bodies (NI PPN 01/21).

The Design System, Route Identity and the First Real Accessibility Measurement

RULE 0-C makes the central design system the only source of truth for every surface. Release 2.7 tested that claim against the import graph rather than the docstring, which is what the rule itself demands, and three of the four findings are the same shape: a central declaration that reached nothing.

🎨 The page-title token lost a specificity contest and reached nothing

--fs-page-title: 2rem (32px) is declared centrally and consumed by .ca-page-title. A dashboard rule selecting .ca-dashboard h1 scored higher and painted 28px. Every heading rendered by the two page shells was the wrong size, against two specs that both declare 32px.

FIXED AND GUARDED The override is now scoped with :not(.ca-page-title):not(.ca-settings-title), and the guard asserts by matches() rather than by computing specificity, with paired positive controls and a non-empty-corpus assertion. It also asserts the size is a token rather than a literal, so the fix cannot be undone by hardcoding the right number.

This is RULE 0-C’s own warning in CSS form. The token was central, documented and correct. The cascade bypassed it, and nothing measured whether it had.

🧭 A page could declare another route’s identity and render a flawless wrong name

🔒 The Defensible Decision Record

web/src/features/public-sector/decision-record.ts. Three mechanisms, each designed against a specific way an evaluation is later challenged.

Weights are locked before any evidence is seen. A SHA-256 hash over a canonical payload of the weightings, criteria and scoring bands, timestamped, and checkable afterwards. Numbers are fixed to four decimal places with negative zero normalised, and strings are JSON-encoded so a separator character in a criterion name cannot forge a field boundary. Band order is preserved because band resolution is first-match. If SHA-256 is unavailable the lock reports UNAVAILABLE rather than falling back to a home-rolled digest, which is the right failure.

A provenance ladder of six classes from contractual down to third-party commentary. A class can be weakened but never promoted, document-backed classes cannot be claimed without the document, and an unrecognised class is rejected rather than silently mapped to the weakest.

Three missing-evidence states that never collapse into one: evidenced, asserted_not_evidenced and not_addressed. “Absent” and “present but weak” are different facts, and a sensitivity check says which gaps can change the ranking and which the buyer should stop chasing.

The understatement runs the other way, and the file says so itself. Only the weight lock has user-visible behaviour. The provenance ladder and the evidence states are DORMANT, complete and unit-tested and reached by nothing outside the file and its tests, because there is no evidence table.
