Section 3Deployment rules

1

One path to production. Local main, committed and clean, then pnpm staging:promote (web, then --project portal after committing the web record), prove it on staging, pnpm staging:verify, then pnpm prod:promote --approval "<owner text with the sha7>". No push by hand, no dashboard deploy, no merge button.

2

One approval is one push. The approval text names the commit's 7 character sha. A standing yes, a plan or silence is not approval. Count pushes across every session of a release, never more than two per session, and state the cost before asking: which workflows fire and which Vercel and Railway deploys follow.

3

RULE 0. No Vercel preview, ever. Every non main git deployment must settle CANCELED. Never edit a vercel.json off main. A push to crowagent-website main is a production deploy of the live site.

4

A variable change needs a rebuild. Vercel applies a changed variable only on the next build, and NEXT_PUBLIC_* values are baked into the browser bundle. After an instant rollback, the next build must be promoted explicitly. A migration that changes what deployed code reads or writes ships in the same promotion as that code.

5

Audit after every push and deploy. Every target verified against the sha, every non main row CANCELED, the product proven on the live host. A partial deploy is never reported as done. Only the driver deploys, rolls back or promotes.

Section 6Secrets and credentials

Between August and October 2026 live keys leaked into transcripts and saved permission rules three ways, every key was rotated on 8 October, and the rotation itself took production down twice. Every rule here is the fix for something that happened. Claude Code is blocked by a hook. Gemini, Kiro and every other tool have no hook and must enforce these rules themselves.
NeverInstead
put a key on a command lineread it inside the process from the environment or a gitignored file. A tool that saves approved commands saves the key with them
run anything that prints values: railway variables, vercel env pull to the screen, cat .env*, printenv, MCP reads of variable valuesfingerprint it: pipe into python -I ~/.claude/hooks/envfp.py, which prints the name, a 10 character hash, the length and the key type only
paste a key into chat, a report, a commit, a test, a fixture or a logname it. If a tool shows you one, report which key and where, by name only
copy a key through chat or an MCP callcopy it in process, store to store, and print fingerprints
rotate, revoke, disable or change a key or variable (any AI other than the driver)leave it to the owner and the driver

Rotation order, or production breaks. Create the new key, put it in every store (Railway services, Vercel production and the Vercel staging environment, the portal Integrations table portal_integrations, the two local .env.local files), rebuild what reads it, prove it works through /readyz and a live page, and only then revoke the old key. The portal reads its Integrations table before its Vercel variables, so a token updated only in Vercel is ignored.

Supabase. Both projects use sb_publishable and sb_secret keys. Legacy JWT anon and service_role keys are disabled on production and staging since 8 October 2026. Env file backups were all deleted on 8 October because several held live keys. Never create one.

Section 8Briefs and reports

1

No brief, no work. Any AI other than the driver works only from a written brief under crowagent-platform/docs/release-<version>/, for example KIRO-BRIEF-<WAVE>.md or GEMINI-BRIEF-<TOPIC>.md. If the brief and the guide disagree, stop and say so.

2

The report names everything. Every file changed, the collected, passed and failed counts per test file, each fix marked code fix or test fix with its reason, rows DONE or NOT DONE, and anything not done with the exact reason. Written to the file the brief names, normally docs/release-<version>/kiro-reports/<NAME>-REPORT.md.

3

Report only what you measured. Never guess a cause and present it as a finding. Before handing back, grep your own text for semicolons, the two dashes and the banned words. That grep is the evidence.
