## 2. Architecture

Build in the **Astro tree only**. It is cleaner than the legacy tree for this.

| Concern | Legacy tree | Astro tree (build here) |
|---|---|---|
| Tool logic | 21 KB IIFE building `innerHTML` | `src/lib/*.ts`, typed and testable |
| Nav | 108 KB injector, manual `?v=` bump per page | `src/data/nav.ts`, data-driven |
| Sitemap | hand-edited `sitemap.xml` | generated by `scripts/build-sitemap.js` |
| Result styling | `applyImportant()` re-applying `!important` | real elements in the cascade |
| Gates | 4 jest suites | **29-step build chain** |

### 2.1 The pattern to copy

`src/pages/tools/ppn-002-calculator/index.astro` (740 lines). Read its docstring
in full before starting; it records three port bugs already paid for:

1. The result rendered off-screen because the port dropped the scroll-into-view.
   Keep `reveal()`.
2. One error sentence for every mistake. Use per-field problems with
   `aria-invalid` and focus moved.
3. The select opened white-on-white. Fixed in `styles/forms.css`, shared by all
   three selects on the site. Reuse `.field__input`, do not restyle.

It also records a deliberate decision: **that page ships no soft-wall gate**,
because it says "no account, no email gate" four times and a gate would
contradict the copy. Same reasoning applies here for Phase 1.

### 2.2 Separation

- `src/lib/tender-matrix.ts` holds all detection logic. Pure functions, no DOM,
  no imports from Astro. Mirrors how `src/lib/ppn002.ts` isolates arithmetic.
- The `.astro` page holds markup and wiring only.

This split is what makes the logic testable and is why `ppn002.ts` could be
parity-tested against the legacy engine at `tests/ppn002-parity.spec.js`.

### 2.3 Detection rules (Phase 1)

Deterministic only. No model, no network.

- **Obligation language**: `must`, `shall`, `is required to`, `will be required`.
- **Question numbering**: leading `1.`, `1.1`, `Q1`, `A1`, `SQ1`.
- **Limits**: word counts, page counts, character counts.
- **Weightings**: percentage patterns, and their sum.
- Every detected row carries the **verbatim source line**. If a value cannot be
  located in the input, drop the row. Never infer.

## 5. Gates

`cd astro && npm run build` runs 29 steps serially. Failure is loud. Budget real
wall-clock time for the chain, separate from the time spent writing the page.

### 5.1 RESOLVED: new routes are exempt from both parity gates

Verified by reading the source, not by assumption:

- `scripts/check-content-parity.js:575` -> `continue; // a new page has no legacy content to lose`
- `scripts/check-seo-parity.js:100` -> `continue; // new page with no legacy equivalent — nothing to regress`

Both resolve a legacy twin via `legacyCandidates(route)` and skip the route when
none exists. **You do not need to build a legacy counterpart.** This was the one
question that could have doubled the work. It does not.

### 5.2 Gates that will bite a new page

- `check-english.js` — no em-dashes, no AI-sounding language
- `check-facts.js` — PPN 002 is always 10%
- `astro check` — types across `.astro`
- `check-design-system.js`, `check-palette-roles.js` — tokens only, no hex
- `check-budgets.js` — page weight
- `check-links.js`, `check-render.js`, `check-csp.js`
- `check-breadcrumbs.js` — the page needs its breadcrumb schema

### 5.3 Legacy tree gates

Only relevant if you also touch the legacy tree, which this spec says not to.
For the record: `tool-teaser-parity.test.js` auto-discovers `js/tool-engine-*.js`
and fails any engine that does not reference `window.CAToolTeaser`.

## 6. Known live defect, legacy tree only

Recorded here because it was found during this analysis and is worth more than
the tool itself.

`js/tool-teaser.js` (154 lines) implements per-slug run counting, a soft wall and
an upgrade strip. **`shouldShowSoftWall()` returns `false` unconditionally**; the
comment says so plainly. The gate is built, wired, tested and switched off.

Separately, the upgrade strip that does run promises "Sign up free, No card
required, 14-day full access" and links to `app.crowagent.ai/signup` with per-tool
UTM attribution. Per `BETA-MODE.md`, `web/app/(auth)/login/actions.ts:630` rejects
any sign-up not on the beta whitelist.

So on the legacy site a visitor who completes a tool is sent to a page that
refuses them, with UTM tags on the journey. **The Astro tree has no teaser at
all**, so the live preview has no lead capture, by design.

Fixing that funnel is a platform decision, not a website one, and is out of scope
here. It is arguably worth more than shipping a second tool.
