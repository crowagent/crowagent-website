## Methodology notes (read before trusting a number below)

- **Text diff %** is a word-multiset symmetric-difference metric, not a literary/LCS diff: every word is bagged, matched 1:1 regardless of position, and the percentage is `(total_words − matched_words) / max(legacy_words, astro_words) × 100`. It answers "how much of the wording changed", not "what moved where". Chosen because a proper O(n·m) diff over several-thousand-word pages × 22 routes was not going to finish in reasonable CI time. Treat the percentage as a strong signal and read the sample text before acting on it.
- **JSON-LD @type differences** are reported as the flattened, sorted set of every `@type` found across all `<script type="application/ld+json">` blocks on the page (including inside `@graph` arrays). A missing type means that structured-data entity is not emitted at all on that side, not merely reordered.
- **Screenshots are evidence for a human, not a pass/fail gate.** The two sites are a deliberate redesign; no pixel diffing is attempted between them.
- Only **title, meta description, canonical, JSON-LD `@type` set, text diff > 2%, and h1 count** are hard failures. Everything else (h2/h3 counts, internal link counts, geometry, scrollHeight) is reported for context only, because the rebuild is intentionally a redesign.

## Cross-route patterns (aggregated — read this before the per-route detail)

- **JSON-LD structured data: 22/22 routes lose or change @type coverage** — this is the single most consistent hard failure across the whole ported set, not an isolated bug.
  - Types present on LEGACY but absent from ASTRO: BlogPosting (8 routes), WebSite (7 routes), FAQPage (5 routes), BreadcrumbList (3 routes), Blog (1 route), Article (1 route)
  - Types present on ASTRO but absent from LEGACY: Organization (15 routes)
  - Net effect: post/page-level schema (`BlogPosting`, `FAQPage`, `Article`, `DefinedTerm`, `WebSite`, `Blog`) is frequently dropped on Astro in favour of a generic `Organization` block, or `Organization` is added alongside an otherwise-intact set. Either way this is live SEO surface and should be verified against the intended schema design, not assumed to be redesign noise.
- **`<title>` differs on 6/22 routes** — all within `/blog/`. Some are additive only (Astro appends " | CrowAgent" where legacy omitted it), but several are substantively reworded (e.g. legacy "Method Statements That Score" vs Astro "How to write a method statement that actually scores"). A reworded `<title>` changes the Google SERP snippet and any inbound backlink anchor expectations — treat the additive and the substantive cases differently when signing off.
- **Meta description differs on 0/22 routes.**
- **`<main>` landmark is entirely absent on ASTRO for 8/22 routes** (`/blog/find-first-public-sector-contract/`, `/blog/frameworks-and-dps-explained/`, `/blog/method-statement-that-scores/`, `/blog/ppn-002-social-value-guide/`, `/blog/private-sector-rfp-pqq-guide/`, `/blog/procurement-act-2023-sme-guide/`, `/blog/regulatory-updates-2026/`, `/blog/social-value-portal-vs-crowmark/`) where LEGACY has one. Astro renders these as an `<article>` with no `<main>` wrapper. This is not in the hard-failure list above (it was not one of the agreed hard-fail criteria) but it is a real accessibility regression — screen-reader "skip to main content" and landmark navigation lose their target on every affected route — and should be fixed before cutover regardless.
